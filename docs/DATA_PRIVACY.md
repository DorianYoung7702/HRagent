# 数据保存与清理

本项目会处理候选人资料。部署者应使用获得授权的数据，并告知使用者处理范围。

源码运行默认使用 `data/`，容器使用持久化卷 `/data`。运行配置保存在 `data/config/runtime.json`（容器为 `/data/config/runtime.json`）；旧配置可通过 `HRAGENT_CONFIG_PATH` 显式复用，迁移步骤见 [部署指南](DEPLOYMENT.md)。

| 数据 | 保存位置与行为 |
| --- | --- |
| 模型 API Key、招聘方身份 | 本机运行配置或环境变量；不要共享运行配置 |
| 平台 Cookie / 登录态 | 本机浏览器 profile；不得提交或随公开发行包分发 |
| PDF 文件 | 系统临时目录，序号文件名；任务结束尝试删除，重启清理遗留目录 |
| PDF 原文 / 文件名 / hash | 不保存到业务数据库；原文发送到配置的模型服务 |
| PDF 结构化筛选结果 | 业务数据库，随工作流保存 |
| 在线简历原文 / 候选人信息 / IM | 业务数据库，按平台任务保存 |
| 工作流日志 | 本地数据目录；反馈问题前检查日志，避免公开个人信息 |
| 跨任务人才档案 | 默认关闭，需显式启用，独立于工作流删除 |

## 人才档案

设置 `HRAGENT_TALENT_ARCHIVE_ENABLED=1` 后，非淘汰候选可归档，并在启动时
从已有筛选结果回填。档案可能包含在线简历原文；一次性 PDF 仍只有结构化结果。
关闭该选项不会删除既有档案，删除工作流也不会清除这些独立档案。

维护者需要彻底清空档案时，先停止服务并确认数据库路径，再通过 SQLite 管理工具
对 `talent_archive_profiles` 执行 `DELETE FROM talent_archive_profiles;`。
先关闭归档配置，避免剩余工作流在下次启动时重新回填。备份需要另行清理。

## 删除的边界

删除临时文件或数据库记录不承诺安全擦除底层磁盘、系统快照或备份。
模型服务商对输入文本的保存策略由服务商决定，HRagent 无法代为删除其记录。
大批 PDF 会占用临时磁盘，框架的上传临时文件和处理队列可能同时存在。

## 公开反馈

优先提供合成简历和最小复现。不得上传真实简历、聊天全文、Cookie、密钥、完整
数据库或内部岗位资料。仓库忽略规则与发布检查只是辅助措施，不替代内容审查。
