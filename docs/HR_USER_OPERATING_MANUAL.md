# HRagent HR 操作手册

适用对象：招聘 HR、猎头顾问、招聘运营人员。  
适用版本：开源单机版，通过源码或 Docker 部署，在浏览器中使用。

## 1. 这套工具能做什么

HRagent用于辅助 HR 完成候选人初筛：

- 根据岗位要求自动解析搜索条件。
- 自动在招聘平台筛选并抓取在线简历。
- 按 HR 的筛选标准判断候选人属于「观察 / 追问 / 排除」。
- 对需要补充信息的候选人生成追问。
- 对合适候选人辅助开聊、收藏、索要简历。
- 在本机保存任务记录，便于复盘和继续处理。

工具不会替代 HR 做最终录用决策。它的定位是减少重复搜索、重复筛简历和重复追问的工作量。

## 2. 使用前准备

请提前准备：

1. 已按 [部署指南](DEPLOYMENT.md) 启动的 HRagent 服务。
2. DeepSeek API Key。
3. 在线筛选需准备可正常登录的猎聘企业账号；PDF 筛选无需平台账号。
4. 稳定网络环境。

使用时请注意：

- 不要让电脑休眠或合盖睡眠。
- 自动筛选过程中不要手动操作自动化浏览器窗口。
- 平台出现验证码、二次登录、安全验证时，需要人工完成后再继续。
- 默认用于本机单用户，不提供多人权限隔离。

## 3. 部署服务

由维护者按 [部署指南](DEPLOYMENT.md) 选择源码或 Docker 启动。无需产品激活码，不依赖桌面安装器。

## 4. 启动与关闭

### 启动

服务启动后，在浏览器打开本地控制台：

```text
http://127.0.0.1:8001
```

### 关闭

先在控制台停止任务，再由维护者关闭服务。源码运行在终端按 `Ctrl+C`；Docker 使用 `docker compose -f infra/docker-compose.standalone.yml down`。不要增加 `-v`，以免删除数据卷。

## 5. 首次配置

首次打开控制台后，先完成顶部的“LLM 配置”。

### 5.1 配置 DeepSeek API Key

1. 在“DeepSeek API Key”输入框粘贴你的 Key。
2. Key 一般以 `sk-` 开头。
3. 点击“保存并继续”或“更新配置”。

DeepSeek API Key 用于：

- 解析 HR 的岗位需求。
- 判断简历是否匹配。
- 生成追问和索要简历话术。

### 5.2 配置招聘方身份

在“招聘方身份 / 公司名”填写对候选人展示的身份，例如：

```text
某某猎头
某某科技 HR
某某人力顾问
```

这个名称会出现在自动生成的 IM 话术中，请填写真实、合规、候选人能理解的身份。

## 6. 登录招聘平台

在“登录设置”中完成猎聘登录。

操作步骤：

1. 点击登录或重新登录。
2. 在弹出的浏览器中登录猎聘企业账号。
3. 如出现验证码、扫码、安全验证，请人工完成。
4. 回到控制台，确认登录状态为可用。

如果长时间未使用，猎聘可能要求重新登录，这是正常情况。

## 7. 创建筛选任务

推荐使用“向导填写”模式。

### 7.1 选择输入方式

控制台提供三种方式：

- `向导填写`：推荐 HR 使用，按字段填写，不容易写错。
- `综合输入`：适合把完整需求粘贴进去，让 AI 自动拆解。
- `分开输入`：适合高级用户手动区分搜索需求和筛选标准。

日常建议优先使用：

```text
向导填写
```

### 7.2 选择平台

如果当前只购买猎聘个人版，请只选择：

```text
猎聘 LPT
```

如果你的版本已开通 BOSS，可同时选择 BOSS。未开通时不要勾选 BOSS，避免产生无效任务。

### 7.3 填写岗位画像

按实际招聘需求填写：

| 字段 | 怎么填 |
|---|---|
| 岗位名称 | 例如：后端开发工程师、海外销售、产品经理 |
| 搜索关键词 | 只写真正要放进搜索栏的词，例如：开发工程师 架构师 |
| 目前城市 | 候选人当前所在城市，例如：深圳 |
| 期望城市 | 候选人期望工作城市，例如：深圳 |
| 经验年限 | 例如：1-5年、3-8年 |
| 目标份数 | 本次希望处理多少份简历，建议 10-30 |
| 学历 | 例如：本科、硕士 |
| 院校要求 | 例如：985、211、双一流、海外留学 |
| 行业/业务背景 | 例如：SaaS、制造业、跨境电商 |
| 技能/能力关键词 | 每行写一条，例如 Python、微服务、团队管理 |

重要规则：

- 城市不要写进“搜索关键词”。
- 年限不要写进“搜索关键词”。
- “20 份简历”不要写进“搜索关键词”。
- 搜索关键词越干净，平台搜索越稳定。

正确示例：

```text
岗位名称：开发工程师
搜索关键词：开发工程师 架构师
目前城市：深圳
期望城市：深圳
经验年限：1-5年
目标份数：20
```

错误示例：

```text
搜索关键词：开发工程师 架构师 深圳 年经验 20份
```

### 7.4 填写筛选偏好

这部分决定 AI 怎么判断候选人。

| 字段 | 用途 |
|---|---|
| 必须满足 | 不满足就不要进入下一轮的硬性条件 |
| 加分项 | 满足后优先看的条件 |
| 需要追问 | 简历没写清时要问候选人的问题 |
| 明确排除 | 出现这些情况直接排除 |
| 开聊岗位名 | 猎聘“选择开聊岗位”弹窗中要选的岗位 |

建议写法：

```text
必须满足：
有 3 年以上 Java 后端经验
做过微服务或分布式系统
最近两段工作稳定

加分项：
有架构设计经验
有带团队经验
有 SaaS 或企业服务经验

需要追问：
是否主导过核心模块设计
是否接受深圳办公

明确排除：
最近一年内频繁跳槽
完全没有后端开发经验
只做过测试或运维
```

## 8. 启动任务

确认以下内容后点击：

```text
一键开始
```

启动前检查：

- 模型 API Key 已配置。
- DeepSeek API Key 已配置。
- 招聘方身份已配置。
- 猎聘已登录。
- 岗位要求已填写。

启动后会进入控制台页面，自动显示：

- 解析进度
- 搜索条件
- 抓取日志
- 候选人列表
- 初筛结果

## 9. 任务运行中要注意什么

运行中请尽量不要：

- 关闭自动化浏览器。
- 手动点击自动化浏览器里的筛选项。
- 让电脑休眠。
- 同时打开多个相同任务。

可以做的事：

- 查看控制台日志。
- 查看已处理候选人。
- 暂停或退出任务。
- 处理验证码或登录验证。

如果平台弹出验证码，请人工完成后等待任务继续。

## 10. 理解筛选结果

系统会把候选人分为三类。

### 观察

表示简历信息已经比较符合要求，可以重点查看、开聊或推进。

常见情况：

- 硬性条件大部分满足。
- 简历证据比较明确。
- 没有明显排除项。

### 追问

表示候选人可能合适，但简历信息不完整，需要进一步确认。

常见情况：

- 年限或城市不确定。
- 某项关键技能没有写清。
- 行业经验可能匹配，但缺少证明。

### 排除

表示与当前岗位不匹配，通常不建议继续处理。

常见情况：

- 明确不满足硬性要求。
- 岗位方向不相关。
- 关键条件冲突。

## 11. IM 跟进与追问

如果开启自动沟通能力，系统会根据结果执行：

- 对“观察”候选人开聊或索要简历。
- 对“追问”候选人发送补充问题。
- 对“排除”候选人不主动联系。

注意：

- 自动话术会使用你填写的“招聘方身份”。
- 第一次使用前请确认身份名称无误。
- 对重要候选人，建议 HR 复核后再继续深入沟通。
- 如平台限制发送、出现风控或验证码，需要人工处理。

## 12. 查看历史任务

控制台可查看历史任务和候选人结果。

建议使用方式：

- 每个岗位单独创建一个任务。
- 岗位要求变化较大时，不要复用旧任务，重新创建新任务。
- 对重要任务保留任务名称，方便后续复盘。

## 13. 仅收藏模式

如果你暂时不想自动发 IM，可以选择：

```text
仅收藏分组，不开聊、不发 IM
```

适合场景：

- 先批量筛简历。
- HR 想先人工复核。
- 当前账号不适合马上触达候选人。

## 14. 常见问题

### 打不开控制台

表现：

```text
http://127.0.0.1:8001 打不开
```

处理：

1. 确认启动服务的终端或容器仍在运行。
2. 访问 `http://127.0.0.1:8001/health` 检查 API。
3. 查看启动终端输出，或运行 `docker compose -f infra/docker-compose.standalone.yml logs --tail=100`。
4. 请维护者依据 [部署指南](DEPLOYMENT.md) 排查端口和前端构建产物；反馈前先移除日志中的个人信息。

### DeepSeek Key 报错

处理：

1. 检查 Key 是否填错。
2. 检查 DeepSeek 账户余额。
3. 检查网络是否能访问 DeepSeek。
4. 更新 Key 后重新保存。

### 猎聘要求重新登录

这是平台正常安全机制。

处理：

1. 打开“登录设置”。
2. 点击重新登录。
3. 完成扫码、验证码或账号验证。
4. 回到控制台继续任务。

### 搜索结果不准

优先检查：

- 搜索关键词是否混入城市、年限、份数。
- 硬性要求是否写得太宽或太窄。
- 城市是否填到了正确字段。
- 院校、学历、年限是否写清楚。

建议把“搜索关键词”控制在 2-5 个核心词。

### 任务中断

常见原因：

- 电脑休眠。
- 网络中断。
- 平台登录失效。
- 平台弹出验证码。
- 电脑同时运行太多程序。

处理：

1. 先不要重复开多个任务。
2. 查看控制台最后一条日志。
3. 需要时停止后重新启动。
4. 如果反复失败，联系售后。

## 15. 数据与隐私说明

源码运行数据默认保存在项目目录中；容器数据保存在 `/data` 命名卷：

```text
data/recruiting.db
data/browser_profiles/
data/logs/workflow_events/
data/config/runtime.json
```

说明：

- 候选人数据保存在本机数据库。
- 猎聘登录状态保存在本机浏览器 profile。
- 模型解析会将所需文本发送给你配置的模型服务。
- 不建议把本机数据库、浏览器 profile、API Key 发给他人。

## 16. 问题反馈需要提供什么

遇到问题时，请尽量提供：

1. 问题发生时间。
2. 当前做了什么操作。
3. 页面截图。
4. 控制台最后几条日志。
5. 是否出现验证码、登录失效、网络异常。

如需日志，位置为：

```text
data/logs/workflow_events/
```

请不要主动发送：

- DeepSeek API Key。
- 猎聘账号密码。
- 候选人完整简历。
- 大量 IM 私聊全文。

## 17. 推荐日常使用流程

每次开始新岗位，建议按这个顺序：

1. 启动 HR Agent。
2. 检查 API Key、招聘方身份。
3. 检查猎聘登录状态。
4. 选择“向导填写”。
5. 填岗位画像。
6. 填筛选偏好。
7. 选择平台。
8. 点击“一键开始”。
9. 观察日志和候选人列表。
10. 复核“观察 / 追问 / 排除”结果。
11. 对重点候选人继续人工跟进。

## 18. 最佳实践

- 每个任务先处理 10-20 份简历，确认筛选标准有效后再扩大数量。
- 硬性条件不要写太多，优先写真正不能妥协的条件。
- “需要追问”只写关键问题，不要把面试问题全塞进去。
- 搜索关键词越简洁，自动搜索越稳定。
- 对高价值候选人，建议 HR 人工复核后再深入沟通。
- 遇到平台风控，不要连续高频重试，先暂停处理。
